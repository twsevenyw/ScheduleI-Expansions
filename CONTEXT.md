### Autonomous updater (recipient does nothing)
- **`Expansions.Updater.dll` is a MelonLoader *plugin*** → deploys to **`Plugins/`**, not `Mods/`. MelonLoader loads `UserLibs` → `Plugins` → raises **`OnApplicationEarlyStart`** → loads `Mods`. In that gap every mod DLL is an ordinary unlocked file, so the plugin copies the new build straight over it and the loader picks it up moments later. Load order verified by reading `Core.Initialize()`/`Core.Start()` IL with Cecil, not assumed.
- **`UserLibs` and `Plugins` are already mapped** by that point — they can't be overwritten but **can be renamed**, so they're move-aside swapped for the next launch, and **the mods are deliberately held back to match** so the running set is never new mods against an old shared library. A release touching no loaded folder lands in one pass. **`Expansions.Core.dll` is therefore always one launch behind** — that's inherent, not a bug.
- Replaced files go to an attic, swept at the **start** of the next launch.
- 21 applier tests (swap, rollback, `.disabled` preservation, hash abort, atomicity, two-pass split, idempotence, unknown fifth mod) + 25 symbol assertions, all passing. The move-aside was also proven on the real, live-locked `UserLibs\Expansions.Core.dll` with the game running.
- The Actions tab no longer has Check/Download/Apply — there is nothing left to press.
- **Not autonomous, unavoidably**: the first install (a plugin that isn't there can't install itself — `INSTALL.txt` flags `Plugins\Expansions.Updater.dll` as the file not to skip); deciding a release exists; and a game patch, which invalidates the interop assemblies the whole suite is compiled against.
- **CI does what it honestly can**: `validate.yml` fails the build if any binary or >1 MB file is committed; `release-verify.yml` re-downloads a published release, re-hashes every zip entry, and rejects undeclared files or anything named Creative Mode. Both were proven green on a throwaway prerelease that was then deleted.
- **Update manifest**: `update-manifest.json`, fetched from `https://github.com/twsevenyw/ScheduleI-Expansions/releases/latest/download/update-manifest.json`. Schema in `docs/update-manifest.schema.json`, contract in `docs/UPDATE-MANIFEST.md`. Key rules: `installDir` doubles as the path inside the zip (`""`/`Mods`/`Plugins`/`UserLibs`); iterate `mods[]` and key off `id` not `name`; `bundledDependencies[]` install only if absent; refuse unknown `schemaVersion` but ignore unknown *fields*. **No releases exist yet → that URL 404s; the client must treat 404 as "nothing published", not an error.**
- **Updater safety**: never delete a mod DLL (orphans NPC folders in saves), and preserve `*.dll.disabled` state — matching only `*.dll` would silently re-enable a mod the player turned off.

## Working Rules (read before acting)
- **NEVER launch the game.** The owner runs it themselves. Repeated agent-driven launches are disruptive and are not an acceptable testing strategy. Ask the owner to run a specific check instead, and give them exact steps.
- **Never kill the game process** if it's already running. Deploy targets use `ContinueOnError`, so file-lock warnings during a build are expected and harmless.
- Verify statically instead: build at 0 errors / 0 warnings, and metadata-check every game/S1API symbol against `<GameDir>\MelonLoader\Il2CppAssemblies\` and `<GameDir>\Mods\S1API.Il2Cpp.MelonLoader.dll` using a `MetadataLoadContext` harness. Late-bind anything uncertain via reflection so an unverified assumption degrades to a logged warning, never a load-time exception.
- Batch anything needing runtime confirmation into a single list the owner can check in one session, rather than trickling requests.

#### Tutorial system — root-cause fix (2026-08-09)
- **Availability is polled continuously** on a 0.5s cache, invalidated on save load, session end, chapter register/withdraw, per-chapter toggle, and reset. A module that wires in late is picked up within half a second — no restart, no reset. **A `false` is never final**, so mods can answer honestly instead of defensively returning `Available`.
- **A blocked chapter contributes zero objectives and is never marked complete.** The line steps over it and comes back in its original position. Its row reads `Blocked - <reason>` in amber (`ReasonFor` existed but nothing displayed it, so blocked was indistinguishable from waiting).
- **Two wedges fixed**: a slot producing no objectives was written off for the whole session (now a 15s retry cooldown); and when the active chapter stopped being first-playable, `_active` was nulled **without cancelling the quest**, orphaning an unfinishable journal entry forever. One rule now covers all three stop conditions (switched off / withdrawn / not ready): a live chapter holds the floor while any objective can still be met, then is **cancelled, never completed**, so it replays in full.
- **Signals latch by design** — right for a mod's Harmony patch, wrong for "press this button", where a player who pressed it earlier watches the objective tick itself off on sight. Core's guide chapter now uses baselined counters.
- `MarkChapterComplete` runs strictly over `PlayedChapterIds` — only chapters that actually contributed objectives.
