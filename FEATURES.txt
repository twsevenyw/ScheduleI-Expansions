  ORIENTATION
  -----------
  This is ROADMAP EXPANSIONS: a shared framework library (EXPANSIONS CORE, in UserLibs), an
  auto-updater (a MelonLoader PLUGIN, in Plugins), and FOUR feature mods (in Mods). Three of the
  four rebuild announced-but-never-shipped Schedule I roadmap features -- Hireable Drivers,
  Police Improvements and Special Customers -- as native-feeling additions. The fourth, QUALITY
  OF LIFE, is a small set of tuning tweaks the owner asked for: faster mixing, a bigger ATM
  ceiling, faster deliveries, and auto-reordering deliveries from the phone.

  Six DLLs ship. Four are mods, one is a shared library, one is a loader plugin.

  BUILT AGAINST GAME BUILD 0.4.6f12                                         *** IMPORTANT ***
  ---------------------------------------------------------------------------------------------
  Every DLL here was compiled against the Il2Cpp interop assemblies MelonLoader generated from
  game build 0.4.6f12 (regenerated 2026-08-08). Those assemblies are a projection of that exact
  GameAssembly.dll.

  On 0.4.6f11 -- the previous public build -- some symbols may bind to the wrong thing or fail to
  bind at all. Nothing is guaranteed to crash, because almost every game touch in this suite is
  late-bound and degrades to a logged warning, but a feature can quietly go missing. Check your
  build in the MelonLoader log: the line reads "Game Version: 0.4.6f12". INSTALL.txt section 6.1
  says where to find it.

  ONE MOD IS DELIBERATELY NOT IN THIS PACKAGE
  -------------------------------------------
  The author of this suite also maintains CREATIVE MODE, a standalone sandbox/cheat toolbox with
  its own hotkey. It is a SEPARATE MOD, it is not part of Expansions, and it is NOT INCLUDED HERE.
  Nothing in this package depends on it, nothing here will load it, and no instruction anywhere
  in these documents expects it to be installed.

  Exactly one thing still names it, and it is harmless: the panel_hotkey comment in
  Expansions.cfg names its hotkey as one to avoid. No part of this package binds that key.

  It does not appear in the tutorial either. Core registers that chapter only when the mod is
  actually loaded, so in this package there is no phantom chapter and nothing in the journal to
  explain away. The line is nine chapters here; on a machine that also has Creative Mode it is
  ten. Both numbers are given wherever they differ.

  main menu where there is nothing to suspend -- the screen logs the reason once and falls back to
  a per-frame cursor unlock.

  THE IN-GAME CONSOLE IS NOT REQUIRED
  ----------------------------------------------------------------------------------------------
  Every verb in this suite is reachable from the Expansions screen or the event chooser. The
  console is still there and the commands below still work, but nothing depends on them. That
  matters because the console has two independent gates that are easy to trip:

    Per-save flag    ConsoleUI.IsConsoleEnabled comes from GameManager.Settings.ConsoleEnabled,
                     persisted in each save's Game.json. On a save where it is false there is no
                     keypress that opens the console.
    Binding / scene  The toggle is the BACKQUOTE key (`) through the new Input System, or hold
                     the left stick and click the right stick on a gamepad. ConsoleUI exists only
                     in the "Main" gameplay scene -- it never opens from the main menu.

  Both are handled from the Actions tab: "Enable and open the console" writes the per-save flag on
  the live settings object and opens the window; "Show the console key binding" reads the live
  binding back out of the game's input asset rather than quoting a constant, so a rebind in the
  game's own options is reported correctly.

==================================================================================================
 3.  EXPANSIONS CORE                                                  [SHIPPED]   v0.1.0
==================================================================================================

  The shared framework the four expansion mods hang off. Deployed as Expansions.Core.dll into
  UserLibs (not Mods) -- MelonLoader scans UserLibs first and registers it as a shared assembly
  resolution directory, so all four mods bind to one copy. It is a plain library, not a MelonMod:
  each expansion mod forwards its MelonLoader callbacks into Core, the first caller becomes the
  frame "driver", and the rest are ignored. One fan-out per frame whether you have one mod
  installed or four.

  Core holds ZERO compile-time references to Assembly-CSharp or FishNet. Every game type is
  reached by name through GameReflection. A renamed game type produces a logged warning, never a
  TypeLoadException that would stop Expansions.Core.dll loading and take all four mods with it.

  Core applies NO Harmony patches of its own.

  Size: 107 source files, ~17,100 lines.

  --------------------------------------------------------------------------------------------
  3.1  MODULE REGISTRY AND LIVE TOGGLES                                            [SHIPPED]
  --------------------------------------------------------------------------------------------
  - Every expansion registers as a module with a stable id, display name, version, description
    and config category. The menu lists them sorted by display name, so the order is stable
    regardless of MelonLoader's load order.
  - Each module gets an "enabled" setting, default on, persisted to Expansions.cfg. Modules never
    declare it.
  - Toggling is live and reversible in BOTH directions -- from our menu, from a third-party
    mod-settings phone app, or by hand-editing the .cfg while the game is running.
  - Each module gets its own Harmony instance, "com.evan.expansions.<module_id>". Disabling
    unpatches only that module. Objects and subscriptions registered with the module's Lifetime
    are disposed in reverse order.
  - Registration is defensive: duplicate ids, categories containing a dot, categories colliding
    with the shared one, and already-claimed categories are all rejected with a warning rather
    than an exception. One bad mod cannot take down the others.
  - A module that throws 10 times in a frame hook during one enable cycle is switched off for the
    session. The PERSISTED toggle stays ON, so it retries next launch.
  - Core warns in the log if an expansion assembly is missing [assembly: HarmonyDontPatchAll],
    because MelonLoader would then auto-patch it under its own Harmony id and the reversible
    toggle guarantee would silently break.

  --------------------------------------------------------------------------------------------
  3.2  THE EXPANSIONS SCREEN                                                       [SHIPPED]
  --------------------------------------------------------------------------------------------
  One screen, two entry points: the "Expansions" main-menu nav entry, and F7 in-game.

  Layout:
      Heading "EXPANSIONS"
      Tab strip: [ Actions ] [ Tutorial ] [ Mods ]   -- opens on Actions
      Page area
      Output pane (Actions tab only)
      Footer: Diagnostics, Close, hint line

  - Built at runtime in uGUI/TMP by cloning live game GameObjects. No asset bundle, no shipped
    fonts, no shipped sprites -- this build has no loadable UI asset path, so cloning is the only
    option, and it also means the screen inherits the exact TMP font asset, SDF material, palette
    and hover behaviour the game uses.
  - Lives on its own DontDestroyOnLoad overlay canvas (sorting order 30000), which is why the same
    code serves the main menu and the in-game hotkey. Rebuilt on scene change; fonts, sprites and
    sounds re-harvested per scene.
  - Panel width switches with the tab: 640px for Actions and Tutorial (an action row carries a
    sentence and a button side by side, and a probe report path is 100 characters that must not
    truncate), and the measured 374px for the module cards, which are pixel-matched to the game's
    own and would stretch if widened.
  - PANEL HEIGHT DERIVES FROM THE DISPLAY: 90% of Screen.height / canvas.scaleFactor, clamped
    between 360 and 1000 canvas pixels, and the page budget is the inverse of that.
  - EVERY LIST SCROLLS -- actions, modules, tutorial chapters, the picker overlay, the event
    chooser and the output pane all run through one ScrollView: a ScrollRect host, a masked
    viewport carrying a TRANSPARENT RAYCAST CATCHER, top-anchored self-sizing content, and an
    auto-hiding scrollbar in a reserved 12px gutter. The wheel is applied by hand from
    Input.mouseScrollDelta with ScrollRect.scrollSensitivity pinned to 0, so there is exactly one
    implementation and it cannot double-apply. Dragging and the scrollbar handle stay on the
    component. PgUp / PgDn / Home / End / arrows work. The raycast catcher is the load-bearing
    part: Unity dispatches IScrollHandler by walking up from the raycast hit, and a Graphic-less
    viewport is not a raycast target.
  - Mods tab: one card per registered module with name, version, description and an
    Enabled/Disabled toggle, in a scrollable list. With nothing installed it says "No expansion
    mods are installed."
  - Tutorial tab: the whole-line controls in a toolbar (Start / Restart, Reset, Enable all,
    Disable all) over one row per chapter, each with its own on/off switch. See 3.7.
  - GAMEPLAY INPUT IS SUSPENDED while the screen is open, by reading the game's own
    StateProperties.UIDefault preset and calling StatePropertiesTransitionHandler.Transition,
    saving and restoring whatever was previously applied. On a scene change the held state is
    DROPPED rather than restored, so the outgoing scene's properties cannot leak into the incoming
    one. The whole path is reflective, so a build where the type moved reports itself unavailable
    and falls back to a per-frame Cursor.lockState write.
  - Every game lookup degrades gracefully: a missing font falls back down a chain, a missing
    sprite falls back to a generated rounded rectangle, missing sounds go silent.
  - The main-menu injector waits 20 frames, then retries to frame 180. If it never injects, the
    whole menu falls back to the IMGUI surface. If it injected once and fails on a later scene, it
    keeps the native screen and logs that F7 still works.

  3.3  THE OUTPUT PANE                                                             [SHIPPED]

  --------------------------------------------------------------------------------------------
  3.5  ACTION REGISTRY (the API modules use)                                       [SHIPPED]
  --------------------------------------------------------------------------------------------
  Process-wide, one of four registries a module contributes to alongside EventRegistry,
  ProbeRegistry and TutorialRegistry:

      Lifetime.Add(ActionRegistry.Register(new ExpansionAction(
          id:          "special_customers.status",
          label:       "Show group status",
          description: "Who is in town, where, when they order and when they leave.",
          isAvailable: () => Director.IsLive,
          invoke:      () => Describe())));

  - ActionAvailability converts implicitly from bool and from string; a string is ALWAYS a
    refusal, and becomes the greyed-out reason shown beside the button.
  - ActionResult converts implicitly from string and bool.
  - Three constructor shapes: plain (Func<ActionResult>), void (Action), and picker
    (choices: + invokeChoice:), the last of which opens a searchable list.
  - ExpansionAction.WithDynamicLabel for a button whose verb changes with state.
  - Group is derived from the id prefix before the first dot, resolved through the module
    registry, so "police_overhaul.x" heads its section as "Police Improvements". group: and
    order: override.
  - Register returns IDisposable; RegisterAll(...) returns one token for the lot.
  - Duplicate ids are rejected with a warning and an inert token.
  - Availability predicates are re-read EVERY FRAME the screen is open, so anything expensive
    sits behind a short-TTL cache: the ConsoleUI heap walk 1s, the NPC registry 2s, session state
    0.5s, the report directory 2s.

  --------------------------------------------------------------------------------------------
  3.6  EVENT REGISTRY AND THE UP-ARROW CHOOSER                                     [SHIPPED]
  --------------------------------------------------------------------------------------------
  An EVENT is a thing that happens to you while you are playing. An ACTION is a row on a menu you
  opened deliberately. They are separate registries because they are separate jobs: an action is
  usually "tell me something" or "put this back", and an event always has a visible consequence in
  the world within a few seconds.

  EventRegistry mirrors ActionRegistry's conventions exactly -- same ExpansionEvent shape, same
  availability and result types, same IDisposable registration through a module's Lifetime.

     Raise the list        UP ARROW during gameplay. The last-fired event is pre-selected, so
                           Enter repeats it.
     Repeat with no list   SHIFT + UP ARROW.
     Pick                  Number keys 1-9, or the arrows plus Enter. Escape backs out.
     Also on the menu      Every registered event is MIRRORED as an ordinary action row under an
                           "Expansion Events" heading, so a hotkey nobody knows about is still
                           discoverable. The row fires the same code, so the availability text,
                           the output line and the repeat target are identical either way.

  The chooser only opens during gameplay, and only when the Expansions screen is not already up --
  that screen owns the arrow keys for scrolling. If the overlay cannot be built at all, the key
  degrades to "repeat the last event", or fires the only available one, and says so.

  Seven events ship: two from Core (a harmless ping that proves the wiring, and the diagnostics
  sweep) and five from Police Improvements. Core's two exist for a structural reason as much as a
  useful one -- a chooser that is empty until a feature mod happens to be installed reads as
  broken, and the chapter that teaches the hotkey has to be completable on a bare install.

  --------------------------------------------------------------------------------------------
  3.7  DIAGNOSTICS HARNESS                                                         [SHIPPED]
  --------------------------------------------------------------------------------------------
  Read-only runtime interrogation. Full probe list in section 11.

  Running it:      Actions tab ("Run all diagnostics probes" / "Run one area of probes"), the
                   footer Diagnostics button, P while the screen is open, the Up-arrow event
                   "Run the diagnostics probes", or "expprobe".
  Output:          <GameDir>\UserData\Expansions-Probe-<timestamp>.md, plus a sidecar
                   -avatars.json when the avatar dump runs. The path is written into the output
                   pane, and "Open the newest probe report" reveals it in Explorer.
  Grep handle:     every probe emits a line "RESULT:<probe_id>:<status>".
  Report tail:     a "Requires a mutating test" section listing the questions no read-only probe
                   can answer -- 20 from Core plus 5 registered by Hireable Drivers -- each with a
                   step-by-step recipe.
  Safety:          each probe is isolated; one throwing is recorded FAILED and the run continues.
                   The report is written even if every probe fails. Probes needing a loaded save
                   report INCONCLUSIVE on the main menu. Every lookup is late-bound.
  Opt-in probes:   a probe that can end the PROCESS rather than merely fail is marked explicit-
                   only. It is skipped by bare "expprobe", by the Diagnostics button, by the
                   Actions-tab runners and by any area or prefix selector, and additionally needs
                   allow_mutating_probes = true and a loaded save.
  Crash journal:   every native step of an opt-in probe writes BEGIN/END through an unbuffered
                   write-through FileStream and flushes to disk before acting. A BEGIN with no END
                   is promoted to Expansions-Probe-quarantine.txt on the next run, reported, and
                   skipped from then on. Converges a bisect in about two runs instead of 31.

  --------------------------------------------------------------------------------------------
  3.8  TUTORIAL DIRECTOR                                                           [SHIPPED]
  --------------------------------------------------------------------------------------------
  Runs the quest line as real S1API quests, 50 XP per chapter via LevelManager.AddXPLocal.
  Progress persists per save. Each mod contributes its own chapter when it loads and withdraws it
  when it is switched off. Nine chapters register in this package. Full content in section 10.

  NOTHING IN THE LINE SELF-COMPLETES. This was rebuilt from the root on 2026-08-09 and the three
  rules it now follows are worth stating, because the previous behaviour was actively misleading:

     1. Availability is POLLED CONTINUOUSLY, on a 0.5-second cache, invalidated on save load,
        session end, chapter register/withdraw, a per-chapter toggle and a reset. A mod that wires
        in late is picked up within half a second -- no restart, no reset. A "false" is never
        final, so a mod can answer honestly instead of defensively claiming to be ready.
     2. A CHAPTER THAT CANNOT BE PLAYED CONTRIBUTES ZERO OBJECTIVES AND IS NEVER MARKED COMPLETE.
        It is withdrawn from the quest, its row on the Tutorial tab reads "Blocked - <reason>" in
        amber, and it is replayed in full later. The old behaviour turned it into one objective
        that ticked itself off after about three seconds, which made a whole chapter disappear
        because of a transient false at quest-creation time.
     3. A live chapter HOLDS THE FLOOR while any of its objectives can still be met. When none can
        -- switched off, withdrawn, or no longer ready -- it is CANCELLED, never completed, so it
        replays from the start rather than leaving an unfinishable entry parked in the journal
        forever.

  Core's own chapters count BASELINED ACTIVITY rather than latching signals for "the player
  pressed this button" objectives. A latch is right for a mod's Harmony patch, and wrong for a
  menu button that exists from the first frame -- a press made an hour earlier would tick the
  objective off the instant it appeared, which is exactly the fake completion this change removes.

  IT HAS ITS OWN TAB, carrying:

      Toolbar        Start / Restart (dynamic label), Reset, Enable all, Disable all
      Intro          What the line is, that mods contribute chapters, and that Start needs a
                     loaded game
      Progress       A live line read from the director's own status
      One row        per chapter: title, description, current state, and an on/off switch

  NATIVE HIRING ON 0.4.6f12                                       [RUNTIME VERIFIED]
  --------------------------------------------------------------------------------------------
  Drivers are hired from the employee-fixer NPC's own shipped conversation: choose to hire an
  employee, pick Driver beside Botanist/Handler/Chemist/Cleaner, then choose one eligible location.
  Five DialogueController_Fixer hooks inject the type, reuse SELECT_LOCATION, validate the dedicated
  driver-slot budget, show driver fees and intercept CONFIRM before vanilla creates a Handler.
  No per-property entries are added to the top-level numbered list. If a future build moves one of
  those hooks, the F7 repair path appears with the exact binding failure.

  WHAT IT IS
  --------------------------------------------------------------------------------------------
  You already have Handlers who shuffle items around inside one property. A Driver does the same
  job BETWEEN logistics properties and dealers. Same hiring, same wages, same bed requirement,
  same five-route grammar. A fresh Veeper is created and boarded only when a valid route departs;
  the remaining new verb is "depart when the trunk holds N items."
  Spawn success uses the live object returned by SpawnAndReturnVehicle; manager registration is
  asynchronous and is never used as immediate success proof. All empty player Veeper duplicates are
  removed once on load across the world. Delivery-vehicle codes, occupied vans and cargo vans are kept.

  A driver is a real vanilla Packager (EEmployeeType.Handler) whose packaging brain is suppressed
  during a trip and whose movement a managed state machine owns. It is NOT a new Employee
  subclass: FishNet's weaver runs at build time only, so an injected subclass would get no RPCs,
  no SyncVars and no spawnable prefabId, and Employee.Initialize would never replicate its name,
  appearance or assignment.

  WHERE EACH SETTING LIVES
  --------------------------------------------------------------------------------------------
     Hire                  Employee fixer: Hire employee -> Driver -> location
     Bed                   Shipped management clipboard, unchanged
     Routes                Same clipboard -- Stations row hidden for drivers, heading reads
                           "Routes · Barn"
     Pickup                Shipped worldspace picker; off-property refused in the game's own
                           hover text
     Drop-off              The clipboard's own ItemSelector list screen -- every owned storage
                           plus recruited dealers, other-property first, plus "Point at it in the
                           world" handing back to the shipped picker
     Departure size /
       set off now         The driver's own dialogue; trip Veeper is automatic
     Fire                  Shipped dialogue option; the mod just cleans up behind it

  DRIVER SLOTS ARE A SEPARATE BUDGET FROM EMPLOYEE CAPACITY
  --------------------------------------------------------------------------------------------
  One driver per logistics property regardless of how many botanists, handlers, chemists and
  cleaners are already there; two at the Barn and Docks Warehouse. Laundering-only businesses
  (Car Wash, Laundromat, Post Office, Taco Ticklers) are excluded from hiring and route endpoints.
  The employee factory's own capacity check is bridged only for the synchronous create call, then
  restored; normal employee validation subtracts drivers, so neither system consumes the other.

     driver_slots_per_property = "*=1,barn=2,dockswarehouse=2"
     drivers_use_employee_capacity = false      (forced -- the legacy setting can no longer enable it)

  A driver remains a network-safe Packager internally, but that implementation detail is hidden:
  the clipboard header is rewritten from Handler to Driver, the route heading is compact enough not
  to overlap its rows, and the avatar wears a blue rolled shirt, charcoal cargo pants, black boots/
  belt and blue cap. Face, hair, tattoos, glasses and facial hair remain unique to the employee.

  Keys are real Property.propertyCode values, read out of shipped save data rather than guessed
  from display names: barn, bungalow, dockswarehouse, manor, motelroom, rv, seweroffice,
  storageunit and sweatshop. Business codes carwash/laundromat/postoffice/tacoticklers are
  deliberately ignored. "*" is the fallback for an unlisted logistics property. Values clamp to
  16, with hard minimums of one everywhere and two at barn/dockswarehouse.

  ROUTES -- EDITED ON THE SHIPPED CLIPBOARD
  --------------------------------------------------------------------------------------------
  A driver is a Packager, so the shipped PackagerConfigPanel already binds five RouteEntryUI rows
  to PackagerConfiguration.Routes. The mod lets that field own the routes, which buys the real
  in-world source/destination picker, the transit-line preview, the item-filter screen, FishNet
  replication and vanilla save/load for free, rather than a mod list that only looks like one.

  Point the clipboard at a driver and you get Bed and Routes; the inherited Stations row is hidden
  because a station assigned to a driver would silently never be worked. The five Route rows are
  the editor:

     From          Storage at THE PROPERTY THE DRIVER WAS HIRED TO. Shelves, racks, packaging
                   stations, presses, pots, mushroom beds, drying racks, ovens, cauldrons, mixing
                   and chemistry stations, loading docks.
     To            Any of the above at another logistics property you own, or a recruited dealer.
     What          The vanilla item filter, including blacklist and multi-item whitelist shapes;
                   blank means "anything the source holds".
     Depart at     Item count. Not a vanilla field, so it lives on the driver's dialogue.
                   0 means automatic: default_depart_threshold_percent of the trunk's capacity.

  PICKUP IS PINNED TO THE HIRING PROPERTY, ENFORCED IN THREE PLACES: inside the game's own
  worldspace picker (a postfix on RouteEntryUI.ObjectValid, so hovering an invalid container shows
  "Driver X only collects from the Barn" and clicking it does nothing), on every pull from the
  clipboard, and on load, where a violating route from an older save or a co-op peer is rejected
  and logged. That is the whole point of hiring at a property.

  DESTINATIONS ARE WIDENED, not narrowed: the same postfix OVERTURNS vanilla refusals for any
  entity that accepts items, because a Handler may only route within its own property and a driver
  crossing town is the entire feature. It only overturns refusals about REACH -- a destination
  that is already this route's own pickup is still nonsense and keeps the vanilla message.

  The clipboard's own worldspace picker is range-limited and a dealer is not an ITransitEntity at
  all, so the mod also drives the clipboard's OWN ItemSelector list screen for drop-offs, with
  dealer names written on through a RefreshUI postfix.

  MIRRORING. The transport loop reads DriverRecord.Routes, so the vanilla field is mirrored into
  it once per tick by POLLING, not by subscribing to RouteListField.onListChanged -- that event is
  a UnityEvent<T> over a game generic, and a collected interop delegate fails silently, which is
  the one failure mode this module refuses to ship. RouteListField mirroring edits existing route
  objects IN PLACE when the shape matches, preserving each row's item filter and RouteEntryUI
  binding.

  A row also times out: depart_after_game_hours (default 4) sends a partly-loaded van rather than
  letting a slow source deadlock the route. 0 waits forever.

  A route is skipped, not failed, when the source has nothing matching, the destination is not
  accepting items, or a dealer destination is already stocked to the cap.

  THE TRANSPORT DECISION -- the load-bearing part                                  [UNVERIFIED]
  --------------------------------------------------------------------------------------------
  The whole feature turned on one fact nobody could settle from metadata: whether civilian vehicle
  prefabs actually carry a VehicleAgent. It is inspector-wired, only police consumers appear in
  the dumps, and it cannot be added at runtime. Rather than bet on it, the mod decides PER TRIP,
  PER VEHICLE and carries both paths:

     DRIVE   The game's own autonomous stack. Navigate on the A* road graph, DriveFlags for
             per-trip style, a reverse-then-teleport stuck ladder, Park at the far end.
     RELAY   The van and driver relay to the far end after a travel-time delay derived from
             straight-line distance -- the same abstraction the game already uses for its own
             supplier deliveries.

  VehicleApi.CanSelfDrive requires a VehicleAgent AND both Seekers AND a VehicleTeleporter. A
  non-null Agent alone is not trusted, because a half-wired one would fail mid-road.

     transport_mode = auto     drive when the vehicle qualifies, otherwise relay  (default)
     transport_mode = drive    driving only; a trip refuses if the vehicle cannot
     transport_mode = relay    always relay, skipping the per-trip check

  BOTH PATHS DELIVER. Only the cross-town leg differs. Collection, deposit, slot locking, capacity
  checks, wages, persistence and the time-skip snap are shared code.

  THE TRIP STATE MACHINE
  --------------------------------------------------------------------------------------------
     Idle -> ToSource -> AtSource -> Loading -> ToDestination -> AtDestination -> Unloading
          -> GoingHome -> Idle,  with Recovering as the failure exit

  Notes on the ones that are not obvious:

     AtSource /       Walks to the entity's reachable access point. After 20 in-game minutes of
     AtDestination    not arriving it warps the last stretch, because storage behind a door the
                      NavMesh will not path through is otherwise a permanently dead route.
     Loading          Moves a batch every LoadMinutesPerStop/6 in-game minutes. Departs when the
                      threshold is met, the source runs dry, patience runs out, or three
                      consecutive transfers move nothing.
     Unloading        Only cargo loaded for the active route can leave the trunk; unrelated cargo
                      and the pre-trip baseline of the same product are preserved. If the far end
                      is full, the driver waits there and retries instead of counting fake trips or
                      returning home with cargo the next route could misidentify.
     Recovering       Files a clipboard issue with a reason and a fix, releases the vehicle claim
                      and any slot locks, hands movement back to vanilla, and cools down 60
                      in-game minutes.

  Every refusal writes a one-line status the panel and the roster action show verbatim: "No
  vehicle assigned.", "Needs a bed and a day's wage in it.", "Off shift. Drivers work 07:00 to
  04:00.", "Nothing to move -- the source is empty or the destination is full."

  DEALERS AS DESTINATIONS
  --------------------------------------------------------------------------------------------
  A recruited dealer can be a route destination. Delivery is a single atomic tick through
  AddItemToInventory, capped at dealer_topup_cap (10, matching the dealer's ten inventory slots).
  The dealer's home building is the parking anchor. No slot reservation is taken, because a dealer
  inventory is not a TransitEntity.

  DEALER CASH COLLECTION IS DELIBERATELY NOT BUILT. Dealer.CollectCash() takes no amount and
  returns nothing, so a safe version means calling it, clawing the same sum back, minting a
  CashInstance into the trunk and laundering it at the far end -- four unverifiable steps whose
  failure mode is duplicating or deleting the player's money.

  SLEEP AND TIME SKIPS
  --------------------------------------------------------------------------------------------
  A trip in flight when the clock jumps is collapsed to its end state in one pass -- collect to
  threshold, snap the outbound leg, deposit, snap the homeward leg -- exactly as the game's own
  NPCSignal_DriveToCarPark.JumpTo does. You wake up to "Delivery completed while you slept", not
  a van abandoned mid-junction. If anything in that resolution throws, the driver is parked at
  home instead and the trip is reset.

  THE F6 PANEL -- READ-ONLY DIAGNOSTICS

     - Per-property driver slot usage.
     - Each driver's state and, if it is not working, the reason in its own words.
     - The route rows exactly as the transport loop currently reads them, flagging any endpoint
       that no longer resolves.
     - Binding failures, including the hiring-desk failure described at the top of this section.

  Still IMGUI and still absolute-rect GUI.Box / GUI.Label / GUI.Button, because this build strips

  PERSISTENCE
  --------------------------------------------------------------------------------------------
  Split, deliberately:

     Routes                 in vanilla PackagerConfiguration.Routes, saved and replicated by the
                            game. That is what buys the real clipboard UI.
     Everything else        in the mod's own blob at
                            <save>\Modded\Saveables\hireable_drivers.json: which employees are
                            drivers, which property each was hired to, an active trip-van GUID,
                            exact blacklist/whitelist filters, departure thresholds, dealer
                            destinations, active-trip cargo manifests and trip counters.

  The roster is rebuilt from scratch on load rather than merged, because the deserialised records
  are new objects and a stale brain would keep editing the previous save's copy.

  Disabling the module first mirrors the latest clipboard rows into the sidecar and clears the
  vanilla RouteListField. Re-enabling restores endpoints AND the exact item filter. This prevents
  the now-ordinary Handler brain from trying to walk a cross-town driver route while the Harmony
  patches are off. Cargo already loaded when a save/reload, scene transition or toggle interrupts
  a trip is resumed from its persisted per-slot manifest instead of becoming stranded trunk stock.

  INTEROP DISCIPLINE
  --------------------------------------------------------------------------------------------

  THE CORE IDEA
  --------------------------------------------------------------------------------------------
  The game has no heat system, no persistent law reputation and no jail. What it DOES have is a
  complete, designer-authored, minute-ticked law scheduler covering patrols, checkpoints,
  sentries, vehicle patrols and curfew -- every entry of which gates itself on one integer,
  LawController.LE_Intensity.

  So this mod does not build a parallel police spawner. It keeps a persistent per-player HEAT
  scalar, maps it onto that integer and the schedule data behind it, and lets the game's own
  scheduler put the officers out. Every write is RAISE-ONLY against the designer's own numbers, so
  AT HEAT 0 THE WORLD IS EXACTLY VANILLA. internalLawIntensity is never written, so Law.json stays
  byte-identical and disabling the module leaves the save unchanged.

  --------------------------------------------------------------------------------------------
  PILLAR 0 -- THERE HAVE TO BE POLICE                police_density, respawn_officers_daily,
                                                                        event_officer_count
  --------------------------------------------------------------------------------------------
  Everything above assumes officers exist. On a long save they often do not, and it is not a mod
  bug: THE MAP'S POLICE ARE A CLOSED SET. The scene ships a fixed number of PoliceOfficer objects,
  parks them in each PoliceStation.OfficerPool, and every patrol, sentry, checkpoint and dispatch
  draws from that pool and returns to it. Nothing in the game creates a new officer. Kill officers
  faster than the game revives them and the pool drains, at which point every police feature --
  vanilla and modded alike -- silently becomes a no-op. That is the "no cops are spawning" report:
  not a broken spawner, a population that ran out.

  THREE FIXES, none of which invents anything the game does not already do.

     Daily revive        NPCHealth already carries IsDead, DaysPassedSinceDeath, a REVIVE_DAYS
     respawn_officers    threshold and a public Revive(). Vanilla only calls it once the corpse
     _daily (true)       has sat out the full threshold, which is far slower than a violent week
                         loses them. This calls the game's own Revive() at each in-game day
                         rollover instead of waiting. No static is written and no object is
                         created. Combat responses and event deployment never revive an officer;
                         a kill remains a kill for the rest of that day.
     Density             police_density (1.0 by default) enlarges foot patrols and DIVIDES each authored
     police_density      post's intensity requirement, so far more patrol, sentry, checkpoint
     (1.0)               and vehicle posts run at once. Sentries and checkpoints keep their
                         authored member limits because their fixed route/stand-point arrays are
                         indexed by member number. 1.0 is vanilla. Snapshotted on enable and
                         written back on disable, the same as every other schedule write.
     Event guarantee     Raids, federal teams and pursuit events check that event_officer_count
     event_officer       (3) live officers are near the scene before they fire, dispatching from
     _count (3)          the nearest station if the map is empty. An event with no police behind
                         it reads as a bug, so it is not allowed to happen.

  "Put the police back on duty" on the Actions tab runs the revive pass on demand and reports the
  count, and the police.officers probe answers the whole question in one place: officers in the
  scene, how many are awake, how many are corpses, station pool sizes, and what stopped the last
  dispatch.

  --------------------------------------------------------------------------------------------
  PILLAR 1 -- HEAT                                                    enable_dynamic_intensity
  --------------------------------------------------------------------------------------------
  A 0-100 float per player, persisted to <save>\Modded\Saveables\expansions_police.json. It
  deliberately survives sleeping -- otherwise it would be a rename of the shipped wanted level,
  which sleeping wipes.

  WHAT RAISES IT
     Committing a crime      the game's own fine for that crime x 0.2, times quantity. The fine
                             values are read from PenaltyHandler AT RUNTIME (17 of 17 on this
                             build), so the mod inherits the game's own severity ranking and
                             re-calibrates itself to future balance patches.
     Getting arrested        +15
     Completing a deal       +1 per $2,000 of contract payment, capped at +15 per in-game day
     During curfew           crime heat x1.5
     By district             Uptown / Suburbia x1.25 -- Downtown / Westville x1.0 --
                             Northtown / Docks x0.85

  With the shipped fine table that works out as: $5 possession -> +1, $50 evading -> +10, $100
  curfew violation -> +20, $150 attempting to sell -> +30.

  WHAT LOWERS IT
     Sleeping           heat_decay_per_day (10) per slept day, NET of whatever already drained
                        live, so a clean day always totals exactly the daily figure
     Lying low          heat_decay_per_clean_minute (0.004) per clean in-game minute, delivered
                        live so the read-out visibly rewards keeping your head down

  THE FIVE TIERS
     Tier              Heat     Officers/post   Checkpoint window   Detection   Search x   Fine x
     ---------------   ------   -------------   -----------------   ---------   --------   ------
     T0  Calm           0-19    1 / 1           shipped               1.00        1.00      1.00
     T1  Alert         20-39    1 / 2           shipped               1.10        1.25      1.25
     T2  Crackdown     40-59    2 / 3           +/- 2 h               1.25        1.50      1.50
     T3  Task Force    60-79    2 / 4           +/- 6 h               1.50        2.00      1.75
     T4  Federal      80-100    3 / 4           +/- 12 h              1.75        2.50      2.00
                                                                     (memory 2.0 at T4)

  The officer bands are a FLOOR, never a ceiling: callers take the larger of the band and the
  designer's own number for that post. A mod called "police improvements" must never quietly staff
  a checkpoint more thinly than the base game did. T1 is exactly vanilla -- v0.4.6 shipped "1-2
  officers instead of 2 all the time". 4 is the game's own hard dispatch cap and is never
  exceeded.

  Heat adds heat/12.5 x intensity_scalar (capped at +8) to the vanilla intensity baseline, clamped
  into the game's own 1-10 range.

  --------------------------------------------------------------------------------------------
  PILLAR 2 -- WHICH LEVERS ACTUALLY GET PULLED
  --------------------------------------------------------------------------------------------
  This is where the design met reality. Of the 31 police tuning statics the plan wanted to
  modulate, 28 turned out to be C# consts that IL2CPP inlined -- writing one is not just useless,
  it can kill the process (see section 15). Only three are real writable statics:
  VisionCone.UniversalAttentivenessScale, VisionCone.UniversalMemoryScale, and
  LawManager.DISPATCH_VEHICLE_USE_THRESHOLD. The live log confirms "3/3 writable".

  So the module drives the world through instance-level and patch-level twins instead:

     Officers per post    the schedule data's own MinMembers / MaxMembers, plus a raise-only
                          clamp on PoliceStation.Dispatch          (enable_schedule_tuning)
     Checkpoint hours     widening the shipped windows on the same schedule data
     Detection            per-officer VisionCone.RangeMultiplier and BodySearchChance -- these
                          are INSTANCE fields and cannot be const-inlined
     Everything else      20 Harmony patch targets on the decision methods themselves

  The module is built so the writable-static count can be ZERO and every pillar still works. The
  police.levers probe reports which statics were writable on your build. Both the schedule numbers
  and the per-officer values are snapshotted on enable and written back on disable, and the
  restore ends in CurrentSettings.Evaluate() so the game re-derives the whole world once from
  fully vanilla data.

  --------------------------------------------------------------------------------------------
  PILLAR 3 -- CONSEQUENCES                                                   enable_consequences
  --------------------------------------------------------------------------------------------
  The shipped arrest is nearly free: $5-$150 per charge, cash only, no debt if you cannot pay, and
  vehicle cargo untouched entirely. This closes that.

     Fine multiplier        the tier multiplier above, times outlaw_fine_multiplier (2.0) while
                            outlawed
     Notice honesty         the surcharge is added to the arrest notice's own penalty list, so
                            the number you read is the number you pay
     Confiscation scope     the stealth argument on RecordPossession and ConfiscateItems is
                            widened, so Advanced packaging stops being a get-out-of-jail card
     Vehicle cargo          contraband in the vehicle you were arrested next to is seized, with a
                            notification naming how many stacks   (confiscate_vehicle_cargo)
     Cash, THEN DEBT        the fine takes your cash; anything you cannot cover is taken out of
                            your ONLINE balance                    (enable_debt)

  THE DEBT LEVER IS THE REAL DIFFICULTY KNOB. Everything else is texture. The shipped economy
  makes cash abundant and online balance scarce -- $10,000/week of ATM deposits, $20,000/24h of
  laundering. A $300 cash fine against a $50,000 pile is nothing; $300 off the online balance is
  the only currency you cannot simply go and earn faster. (Note that the Quality of Life module
  raises the ATM ceiling to $25,000 by default, which weakens this lever. See section 8.)

  Self-calibrating charge: the module measures your cash across the arrest notice opening and
  closing, and charges only the shortfall. If vanilla already charged, it tops up; if vanilla
  charged nothing, it charges in full. It logs which it learned, and the police.world_state probe
  reports it.

  --------------------------------------------------------------------------------------------
  PILLAR 4 -- OUTLAW STATUS                                                        enable_outlaw
  --------------------------------------------------------------------------------------------
  Heat is the pressure; Outlaw is the phase change. A latched three-state ladder that changes
  RULES rather than the world.

     CLEAN  -> MARKED     heat reaches outlaw_heat_threshold (90)
     MARKED -> HUNTED     a second federal encounter, or a second arrest while outlawed
     Down one tier        outlaw_clear_days (3) consecutive in-game days with no crimes and no
                          arrests, the "Serve out one outlaw tier" action, or the legal fee

  Dropping a tier also pulls heat back below the latch threshold so you do not instantly re-latch.

  While outlawed: every officer is permanently flagged as knowing you on sight, body searches
  always find something, vehicle searches always find something, pursuits do not evaporate on a
  brief loss of line of sight (the timeout deadline is doubled rather than cancelled, so a chase
  still ends), de-escalation is floored at Investigating rather than dropping to nothing, and
  fines are doubled.

  OUTLAW ECONOMICS. Being outlawed now costs money as well as freedom:

     Dealer surcharge     every recruited dealer takes outlaw_dealer_cut_bonus (5 points) on top
                          of their flat 20%. A hazard premium.
     Customer snitch      every unlocked customer is outlaw_snitch_bonus (10 points) more likely
                          to call the police. Shipped chances already span 0-67%, so this stays
                          inside the existing spread.
     Card-only vendors    the realtor and the car dealership refuse to serve you, through a
                          prefix on ShopInterface.Open that says which shop and why. Cash trade
                          is unaffected -- you are an outlaw, not bankrupt.

  All three are SNAPSHOTTED AND REVERTED on status change, on disable, AND ON SCENE UNLOAD. Dealer
  and customer data are ASSETS, not scene objects, so a raised cut or snitch chance would
  otherwise follow you into the next save.

  "What is outlaw status costing me?" on the Actions tab itemises the whole bill, including how
  many dealers and customers are actually affected right now.

  THE LEGAL FEE. "Pay the legal fee ($25,000)" buys one tier down with money instead of time.
  Cash first, then the bank balance. Priced at the Barn, so it is a real mid-game decision.

  PILLAR 5 -- FEDERAL AGENTS AND STAKEOUTS               enable_federal_agents, enable_stakeouts

  STAKEOUTS. A federal event fired while you are inside a property you own posts the agents at

  IDENTITY, AND THE "LEROY" BUG. A cloned agent used to keep the donor officer's NPC id, so every

  LOOK: built by SUBTRACTION from a real officer. Drop the police cap and the marked bulletproof
  vest, keep a plain navy vest, swap the duty belt for an ordinary belt, add a charcoal blazer,

  PILLAR 6 -- PROPERTY RAIDS                                              enable_property_raids

  --------------------------------------------------------------------------------------------
  PILLAR 7 -- CUSTODY, EQUIPMENT AND INFORMANTS
  --------------------------------------------------------------------------------------------
  CUSTODY (enable_jail_day). The game has no jail interior, so an outlaw arrest reuses what the
  game does have: it skips to the game's own wake time and charges a processing fee of one day of
  your actual payroll (minimum $250, scaled by jail_processing_fee_scalar). The charge and the
  lost day are ANNOUNCED BEFORE the clock moves, and the whole thing is deferred 30 frames off the
  FishNet release RPC rather than run re-entrantly inside it.

  EQUIPMENT LOSS (enable_equipment_loss). An outlaw arrest also takes the Tools and Equipment
  categories out of your inventory, through the game's own RemoveAmountOfItem. It deliberately
  excludes Agriculture, Furniture, Lighting and Storage -- seizing pots and lamps is theft, not
  policing.

  INFORMANTS (enable_relationship_damage). CallPoliceBehaviour's finish hook records who dialled.
  When the arrest lands, that person loses snitch_relationship_damage (0.25 of the shipped 0-5
  scale) and the game tells you their name. Observed live: "Relationship dropped by 0.25 with
  Cranky Frank for calling the police."

  --------------------------------------------------------------------------------------------
  HOW THE MOD TALKS TO YOU -- PHONE MESSAGES, NOT TOASTS
  --------------------------------------------------------------------------------------------
  A toast tells you something happened and then it is gone. A federal raid that cost you $8,400
  and half a container deserves better than three seconds in the corner, so every substantive
  event now arrives as a PHONE TEXT you can re-read.

  THE SENDER is a dedicated, non-physical contact -- "Dispatch Office", id
  expansions_police_dispatch. S1API messaging needs an NPC to send from, and using a federal-agent
  clone was exactly what produced the LeRoy attribution bug and would also drop a temporary chase
  NPC into your contacts list. Dispatch is one intentional entry, has no body in the world, and is
  cleared out of the Customer / Dealer / Supplier filters so it only appears when it texts you. It
  exists whenever the DLL is loaded; disabling the module just stops the sending.

  TEXTED: heat-tier changes, outlaw transitions, a federal team arriving and leaving, the raid
  outcome and what was taken, a fine settled out of cash and bank, the legal fee, informant
  fallout by name, equipment seized, a vehicle searched, being booked in, and early release.

  STILL A TOAST, deliberately -- these are the cases where reaching for the phone is too slow or
  the phone is not up yet: the inbound-raid warning, the custody day-skip, a card-only shop
  refusing an outlaw, and menu-action feedback. A text also falls back to a toast if the contact
  is not up yet (main menu, pre-save), so a substantive event is never silent.

  --------------------------------------------------------------------------------------------
  WHEN EVENTS FIRE -- THE RANDOMISED SCHEDULER                          enable_event_scheduler
  --------------------------------------------------------------------------------------------
  Firing the instant a threshold is crossed makes the police feel like a tripwire. The scheduler
  decouples WHEN from WHETHER: eligibility (heat, outlaw status, cooldowns) still lives with the
  directors, and this only decides when an eligible event is allowed to roll.

     Federal rolls    every federal_interval_hours_min..max (6-18) in-game hours
     Raid rolls       every raid_interval_hours_min..max (8-24) in-game hours, while outlawed
     Grace            no scheduled event fires within event_ready_grace_minutes (30) in-game
                      minutes of a save load, so nothing lands while the world is still settling
     Determinism      seeded per save, so the cadence is reproducible rather than frame-luck
     Refusals         a roll that comes up ineligible re-queues immediately, so it does not spin
                      every hour retrying

  Manual triggers -- the Actions tab and the Up-arrow chooser -- ALWAYS bypass the schedule, and
  bump the cadence afterwards so a test fire does not immediately double up with a scheduled one.
  Setting enable_event_scheduler false restores the old fire-as-soon-as-eligible behaviour.

  five) and the shipped 1,000-unit hard clamp.

  THE PRODUCT ALLOW-LIST                       product_allow_list / enforce_allow_list_on_member_deals
  --------------------------------------------------------------------------------------------
  Comma-separated, default "Granddaddy Purple, Cocaine, Diddy's Powdered Semen". It decides what a
  group is allowed to ask for; the archetype's own taste then chooses WITHIN the list. Leader bulk
  contracts always honour it. Member street deals honour it when
  enforce_allow_list_on_member_deals is true (default): affinities are biased to allowed drug types
  and GetProductEnjoyment is zeroed for off-list products before the game builds the offer.

  Resolution scans ItemManager.GetAllItemDefinitions() filtered to products -- which is where
  mod-created definitions land, and the default list already contains one -- unioned with
  ProductManager's listed, discovered and favourited arrays. Three passes: exact display name,
  then internal id, then relaxed (case, spaces and punctuation stripped).

  A name that matches nothing is reported BY NAME and skipped, never guessed at, because a
  contract for a product that does not exist is a contract you can never fulfil. Unresolved names
  are RETRIED EVERY 20 SECONDS rather than latched, because another mod can register products
  after a save has finished loading.

  Leave product_allow_list empty and there is no restriction at all: groups go back to buying
  anything you have listed. "Show the product allow-list" on the Actions tab and the sc.products

  PER-VISITOR RANDOMISED APPEARANCE
  --------------------------------------------------------------------------------------------
  Each archetype carries a WARDROBE -- pools per avatar slot, each with its own probability --
  rather than one fixed recipe. The silhouette pieces stay near-certain (combat boots and an open
  vest at 85% for the bikers, a blazer at 85% for the businessmen), so the archetype still reads
  at a glance while no two members are the same person. Hair, face, build, skin, shirt colour,
  hats, glasses, tattoos and props all vary.

  xorshift32 -- never UnityEngine.Random. It is generated once on arrival from the elapsed day
  plus a persisted per-save visit counter, and is saved. So a reload rebuilds exactly the same
  faces, a co-op guest computes the same ones, and the next visit brings different people. The
  cache key includes the SLOT, not the member index.

  AvatarAssets contains exactly the harvested catalogue and nothing invented; the sc.archetypes
  probe fails loudly if a future edit introduces an unknown path. Skirts are supported -- female
  members can get MediumSkirt plus FemaleUnderwear, and the factory refuses a tucked top with one.

     pin_visitor_schedules   ClearActions() + Disable() + SetCurfewMode(false), host-side, on
                             settle, park and placement.
     post_watchdog           A 4 Hz check that warps back anyone more than post_drift_radius_m
                             (8 m) from their post or post_drift_depth_m (3 m) above or below it.
                             DISARMED until the director knows whether a group is in town, so it

  THE INTERACTION FIX                                                  [SHIPPED, UNVERIFIED]

 8.  QUALITY OF LIFE                                                      [SHIPPED]   v0.1.0
==================================================================================================

  Module id:        tweaks
  DLL:              Expansions.Tweaks.dll  -->  Mods\
  Config category:  Tweaks_01_Main
  Displays as:      "Quality of Life"  (the MelonLoader banner and the Mods tab both say so)
  Size:             26 source files, ~4,150 lines
  Contributes:      8 actions, 4 probes, 11 Harmony patch targets (10 applied at default
                    settings), 11 settings + enabled, a 5-objective tutorial chapter, one save
                    blob

  Four small tweaks that share one toggle card. They have nothing in common mechanically, and that
  is the point of shipping them together: each is a handful of lines against a different
  subsystem, and four toggle cards for four numbers would be worse than one card for a category
  you can reason about.

  What they DO share is the rule that made all four tractable: NONE OF THEM WRITES AN IL2CPP
  CONST, and none of them patches a small getter and hopes it was not inlined. Every one moves a
  value that has real storage, so the change cannot be optimised away, and every one is put back
  exactly on disable. Every multiplier reads the same way -- bigger is faster -- and 1.0 is
  byte-identical to not having the mod installed.

  --------------------------------------------------------------------------------------------
  8.1  FASTER MIXING                                                       enable_faster_mixing
  --------------------------------------------------------------------------------------------
     mix_speed_multiplier            2.0 by default. A one-hour mix takes thirty minutes.
     mix_speed_applies_to_employees  true by default.

  Applied to each station's own per-item mix time, so the station screen and the management app
  show the new figure too -- the UI never disagrees with the clock. Stations are scaled on Awake
  (both MixingStation and MixingStationMk2, patched by declaration so the base lookup cannot hand
  back the same MethodInfo twice) and again as a belt-and-braces pass in MixingStart, which is the
  one moment the duration is read and committed.

  Turning mix_speed_applies_to_employees OFF installs one extra patch on
  GetMixTimeForCurrentOperation, which is the only lever that can distinguish who started a mix.
  It is BEST-EFFORT by nature: the station is shared, so the exclusion depends on the game having
  recorded the chemist as the station's user before the mix begins, and the station screen still
  shows the sped-up figure. That is why the default is on -- an honest speed-up beats a leaky
  exclusion.

  --------------------------------------------------------------------------------------------
  8.2  WEEKLY ATM DEPOSIT LIMIT                                        enable_atm_deposit_limit
  --------------------------------------------------------------------------------------------
     weekly_deposit_limit            25,000 by default. Vanilla is 10,000.

  The game's own ceiling is a const, so it is never written. Instead the module carries the
  DIFFERENCE on the week-to-date counter: the counter is offset so the game's own arithmetic
  arrives at your ceiling instead of its own. The offset is re-applied after Atm.WeekPass (which
  writes a true value over it), lifted for the duration of MoneyManager.GetSaveString so the
  serialised counter stays honest, re-applied after MoneyManager.Load, and cleared entirely on
  scene unload and on disable. The ATM interface's caption is repaired in its Update so the
  on-screen allowance matches.

  Lower than vanilla works too, if you want it tighter. Note that Police Improvements deliberately
  takes unpayable fines out of your ONLINE balance, and its difficulty tuning assumes the vanilla
  $10,000 ceiling -- raising this weakens that lever. Both mods are shipping with their own
  defaults; if you want the police pressure back, set weekly_deposit_limit = 10000.

  --------------------------------------------------------------------------------------------
  8.3  FASTER DELIVERIES                                              enable_faster_deliveries
  --------------------------------------------------------------------------------------------
     delivery_speed_multiplier       2.0 by default. A delivery arrives in half the time.

  Applied at DeliveryShop.GetDeliveryTime(itemCount), which is the single funnel: the order screen
  prints it and SubmitOrder bakes it into the new DeliveryInstance.TimeUntilArrival. Scaling that
  one result moves the quoted ETA and the truck together, from one postfix, with nothing to
  restore on disable.

  There is deliberately no ETA-text patch. The countdown on the phone IS TimeUntilArrival,
  decremented one per game minute, so the number shown is the literal number of minutes left
  before and after. Scaling the tick instead would make the countdown run at double speed and the
  quoted ETA a lie.

  A vanilla quote that is not itself a plausible duration (more than 10,080 game minutes, i.e.
  seven in-game days) is handed straight back UNTOUCHED and counted, because scaling a number that
  was already wrong only hides where it came from.

  --------------------------------------------------------------------------------------------
  8.4  THE DELIVERY ETA BUG, AND THE REPAIR                            *** READ THIS ***
  --------------------------------------------------------------------------------------------
  An earlier build of the delivery tweak scaled the three DeliverySettings fields
  (DeliveryTimePerItem, MinimumDeliveryTime, MaximumDeliveryTime) directly on the settings asset.
  Those are not primitives: each is a SerializableSettingsField<T>, and reading .Value off that
  generic wrapper through reflection does not come back as the number. IT CAME BACK AS A RAW
  32-BIT PAYLOAD -- 807768992, identical for all three fields. Read as a float, that bit pattern
  is a denormal that prints as 0, which is why the per-item time logged as "0 -> 0". Half of it,
  403884480, was then written back as the delivery floor and ceiling, so every subsequent order
  was clamped to 403,884,480 game minutes and the phone showed 6731407h -- about 768 years.

  IF YOU EVER RAN THAT BUILD, YOU HAVE ORDERS THAT WILL NEVER ARRIVE. This build fixes it two
  ways:

     Prevention  The module never writes to the settings asset again. It quotes through the
                 game's own function instead of second-guessing its storage, which removes the
                 entire class of mistake.
     Repair      On every settle, including after a save load, a sweep inspects live deliveries
                 and rewrites any countdown that is not a plausible duration, re-quoting a
                 replacement from a live delivery shop. It only touches implausible values, so on
                 a healthy save it writes nothing at all. The sweep retries for about twenty
                 seconds after the world settles, because repairing a poisoned countdown needs a
                 shop to quote from and the phone's shops are not necessarily built on the frame
                 everything else resolves. "Repair stuck deliveries" on the Actions tab is the
                 manual handle.

  It works. From the owner's log:

     Repaired delivery 'a97f64c4-...' from Gas-Mart (Central): minutes to arrival
       403883121 -> 180 (3h 0m). Nothing else about the order was changed.
     Delivery repair (the startup sweep): 2 order(s) inspected, 2 repaired, 0 left for a later
       pass.

  --------------------------------------------------------------------------------------------
  8.5  AUTO-REORDER                                                        auto_reorder_enabled
  --------------------------------------------------------------------------------------------
  A TICK BOX ON EVERY ROW of the phone's Deliveries app -- both the active orders and the past
  orders, since those are the two places you already manage a delivery. Tick it and that exact

     auto_reorder_min_balance   1,000 by default. A standing order will not fire if paying for it
                                would leave you below this. Checked against whichever balance the

     auto_reorder_notify        true. The game's own notification fires whenever a standing order

 9.  THE AUTO-UPDATER                                                     [SHIPPED]   v1.0.0
==================================================================================================

  File:  Expansions.Updater.dll  -->  Plugins\    (NOT Mods -- this matters, see below)
  Size:  17 source files, ~2,910 lines

  NOTHING IS EVER ASKED OF YOU. There is no update prompt, no button and no restart notice. The
  Actions tab has no Check, no Download and no Apply, because there is nothing left to press.

  WHY IT IS A PLUGIN AND NOT A MOD
  --------------------------------------------------------------------------------------------
  That distinction is the entire mechanism. MelonLoader loads UserLibs, then Plugins, then raises
  OnApplicationEarlyStart, and only THEN loads Mods. In that gap every mod DLL is still an
  ordinary unlocked file, so a newer build can simply be copied over it and the loader picks up
  the new one a moment later.

  Put this file in Mods and it loads at the same time as everything it is supposed to replace, and
  the whole mechanism is gone. It is not optional and it does not go in Mods.

  The load order was verified by reading MelonLoader's own Core.Initialize() / Core.Start() IL
  with Cecil, not assumed.

  WHAT HAPPENS EACH LAUNCH
  --------------------------------------------------------------------------------------------
     1. Anything the last session downloaded is verified again and swapped in, before any mod
        loads.
     2. A check for the next release starts on a background task and the launch carries on.
        Offline, or no release published, is one log line and nothing else:

           [Expansions_Updater] No release is published at <manifest url> yet. Nothing to do.

  RULES IT WILL NOT BREAK
  --------------------------------------------------------------------------------------------
     - NOTHING IS DELETED, EVER. The file being replaced is moved into
       UserData\Expansions.Update\attic\ and stays there for a whole session, so the previous
       build is recoverable by hand. Deleting a mod DLL would orphan that mod's NPC folders
       inside your saves.
     - A MOD YOU SWITCHED OFF STAYS OFF. Both Foo.dll and Foo.dll.disabled are matched, and the
       update is written to whichever one exists. Matching only *.dll would silently re-enable a
       mod you turned off.
     - SHA-256 is checked on the zip before it is opened, on every file extracted from it, and
       again on every file immediately before it is written. One bad hash abandons the whole
       update and touches nothing.
     - IT IS ALL OR NOTHING. If any write fails, every write already made is undone.
     - UserLibs and Plugins are already mapped by the time the plugin runs. They cannot be
       overwritten, but they CAN be renamed, so they are move-aside swapped for the next launch --
       and THE MODS ARE DELIBERATELY HELD BACK TO MATCH, so the running set is never new mods
       against an old shared library. A release that touches no loaded folder lands in one pass.
       Expansions.Core.dll is therefore always one launch behind. That is inherent, not a bug.

  Verification: 21 applier tests (swap, rollback, .disabled preservation, hash abort, atomicity,
  two-pass split, idempotence, an unknown fifth mod) and 25 symbol assertions against the
  installed MelonLoader, all run by the publisher before a release is cut. The move-aside was also
  proven on the real, live-locked UserLibs\Expansions.Core.dll with the game running.

  SETTINGS (in [Expansions], see section 12)
  --------------------------------------------------------------------------------------------
     auto_update           true.  false means the updater does nothing at all -- including
                           nothing with anything already downloaded. There is no manual
                           alternative, by design.
     update_channel        "stable". Anything else also picks up pre-releases.
     update_manifest_url   The project's GitHub release asset. A GitHub owner/repo shorthand also
                           works. Empty disables update checking entirely.

  WHAT IT CANNOT DO, UNAVOIDABLY
  --------------------------------------------------------------------------------------------
     - The FIRST install. A plugin that is not there cannot install itself, which is why
       INSTALL.txt flags Plugins\Expansions.Updater.dll as the file not to skip.
     - Decide that a release exists. Somebody has to publish one.
     - Survive a game patch. The interop assemblies the whole suite is compiled against are a
       projection of GameAssembly.dll, so a game update invalidates them and needs a new build.

==================================================================================================
 11.  DIAGNOSTIC PROBES -- all 53
==================================================================================================

  53 probes when all four feature mods are enabled: 18 in Core (17 always-on plus 1 opt-in), and
  11 + 10 + 10 + 4 from Special Customers, Hireable Drivers, Police Improvements and Quality of
  Life. Modules add and drop their own probes through their Lifetime, so the registered set tracks
  which modules are on. Core alone reports "Diagnostics: 18 probe(s)." in the log.

  Per-mod probes are described in sections 5 to 8. Core's 18, by report area:

    1. Vehicles, drivers and employees
       vehicles.agent_presence    Do civilian vehicle prefabs and live vehicles carry a
                                  VehicleAgent?
       vehicles.agent_surface     VehicleAgent's real runtime surface and kinematic threshold.
       employees.prefab_wages     What the four employee prefabs really cost to hire and keep.

    2. Police
       police.penalty_values      The real fine and penalty values.
       police.tuning_writability  Which of the 31 police tuning statics are real mutable fields
                                  and which did IL2CPP inline as consts? Read-only: it reads each
                                  field's IL2CPP attribute flags, which is the runtime's own
                                  answer, so no write is needed.
       police.tuning_statics      *** THE ONE OPT-IN PROBE. IT CAN END THE GAME PROCESS. ***
                                  Confirms the above by sentinel-writing only the fields proved
                                  writable and restoring each in a finally, inside one frame.
                                  Needs its exact id on the command line, allow_mutating_probes =
                                  true, and a loaded save. Journalled, so a hard crash is
                                  attributed to one field and that field is skipped from then on.
       police.type_surface        Does PoliceOfficer declare what the patches target, and do
                                  LE_Intensity / Evaluate() exist?
       police.vms_board           Can VMSBoard text be set, or is the curfew-sign idea decoration
                                  only?

    3. NPCs, spawning and appearance
       net.spawnable_prefabs      What is in FishNet's SpawnablePrefabs, and is "PoliceNPC" one?
       npc.avatar_dump            Dump every shipped NPC's AvatarSettings to disk (sidecar).
       npc.asset_catalogue        Which clothing and accessory asset paths does the game use?
       npc.avatar_shape_keys      How many arguments does Avatar.ApplyShapeKeys take here?
       npc.customer_census        How many Customers and NPCs exist, so the visitor-pool overhead
                                  claim can be honest?

    4. Version and detection baselines
       version.sources            Which version source is readable, and which one does
                                  SaveManager.GetVersionNumber parse?
       version.detection_baselines  Today's structural fingerprints for the official-feature
                                  detector.

    5. Persistence and identity
       identity.player_code       What identifies this player and this save on disk?

    6. Runtime constants
       runtime.constants          Shipped values of the statics the plans read at runtime rather
                                  than hard-code.

    7. Environment
       env.runtime                Which loader, API and interop assembly versions produced this
                                  report?

  The other report areas are "8. Special Customers", "9. Hireable Drivers", "9. Police
  Improvements" (yes, both are 9 -- cosmetic) and "Quality of Life".

  RECOMMENDED FIRST RUN: load a save, run everything, then quit, relaunch, load the same save and
  run it again. Diffing the two reports is what settles whether Player.PlayerCode is stable for
  the same human across sessions -- an open question that decides how per-player heat is keyed.

 12.  CONFIGURATION -- every setting in the suite
==================================================================================================

  EXPANSIONS uses one file: <GameDir>\UserData\Expansions.cfg (TOML, via MelonPreferences). Safe
  to hand-edit while the game is running -- module toggles apply live. 120 keys across five
  sibling top-level tables. The "_01_Main" suffix is the Schedule I community convention that
  third-party in-game mod-settings apps (ModsApp, Prowiler's Mod Manager) key off, so following it
  gets these an in-game settings UI for free.

  Two names to know: the Police module's id is "police_overhaul" but its category is
  PoliceImprovements_01_Main (the id predates the display name), and the Quality of Life module's
  id is "tweaks", so its category is Tweaks_01_Main.

  Every module automatically gets an "enabled" key (bool, default true). Modules never declare it.

  ----------------------------------------------------------------------------------------------
  MelonPreferences hands the identifier to its TOML writer unquoted, a dot is read as a table
  path, the module gets nested inside the parent table, and every entry it tries to write is
  SILENTLY DISCARDED. This was a real bug in this project: every module's "enabled" entry was
  never reaching disk, so disabling a module was lost on restart. Core now refuses to register a
  module whose category contains a dot.

  THE LOG SHOULD READ "5 Mods loaded." AND "2 Plugins loaded." AND "0 UserLibs loaded."
  Five mods = the four expansion mods plus S1API, which MelonLoader also counts as a mod. Two
  plugins = the updater plus S1APILoader. Zero UserLibs is CORRECT: Expansions.Core.dll is a
  library, so the assembly loads (the line above says so) but no mod is found in that folder.

  Expansions.Core.dll MUST be in UserLibs, not Mods. MelonLoader scans UserLibs before Plugins and
  Mods and registers it as a shared assembly search directory, so all four mods bind to a single
  copy. A copy sitting next to a mod in Mods\ would shadow it.

  Expansions.Updater.dll MUST be in Plugins, not Mods. See section 9 -- in Mods it loads at the
  same time as the files it exists to replace and the whole mechanism is gone.

  The four expansion mods are independent. Install any subset -- Core handles any combination and
  produces exactly one per-frame fan-out regardless. Core alone still gives you the Expansions
  screen, its 21 actions plus the two Core event rows, the 18-probe harness and five tutorial
  chapters.

  Every project's <Version> matches the version its MelonInfo attribute declares. Expansions.Core
  is 0.1.0 and has no MelonInfo, because it is a library rather than a mod.

  BUILDING FROM SOURCE
  ----------------------------------------------------------------------------------------------
         dotnet build src\Expansions.sln -c Release

     Auto-copies Expansions.Core.dll into <GameDir>\UserLibs, Expansions.Updater.dll into
     <GameDir>\Plugins and the four mod DLLs into <GameDir>\Mods on success.

     It builds with 0 errors and 0 warnings. The deploy target uses ContinueOnError, so a
     file-lock warning while the game is running is expected and harmless -- the copy is simply
     skipped. Pass -p:ExpansionsDeployDir= to skip the copy entirely and get a silent build.

     Target framework is net6.0. References resolve against
     <GameDir>\MelonLoader\Il2CppAssemblies and <GameDir>\MelonLoader\net6, plus the S1API.Forked
     3.1.7 NuGet package. Nothing is copied local: the S1API NuGet is explicitly excluded from the
     output because S1APILoader provides the runtime DLL. Expansions.Updater deliberately
     references nothing but MelonLoader and the BCL, because it runs before Unity's scripting
     domain is usable.

     If you change the game path, edit the GameDir property in src\Directory.Build.props.

  ----------------------------------------------------------------------------------------------
     Double-click Push-Update.cmd at the repository root. It works out the next version, builds,
     verifies the plugin against the installed MelonLoader (25 assertions), runs the 21 updater

     commits, pushes, tags and creates the GitHub Release. Full runbooks: docs\RELEASING.md and
     docs\AUTO-UPDATE.md.

     Releases are cut LOCALLY, not in CI, because the projects reference ~29 MB of Il2Cpp interop
     assemblies generated from the installed game, which cannot legally or practically live in the
     repository.

 14.  WHAT TO TEST FIRST
==================================================================================================

  Ordered so an early failure saves you the later ones. Do them on a save you are willing to lose.

   1. Load a save, press F7, and check the shape of the screen.
      PASS: an ACTIONS / TUTORIAL / MODS tab strip; the action list scrolls with the mouse wheel
      and with PgUp / PgDn / Home / End; there are five module cards' worth of groups plus an
      "Expansion Events" heading; and the Police group has twelve rows.
      FAIL, no Police heading: the log will say "Registered 0/12".

   2. Press UP ARROW while walking around.
      PASS: a short list appears in the middle of the screen, the arrow keys move the selection
      and your character does not move. Fire "Test the event hotkey", then press SHIFT+UP.
      FAIL: check event_hotkey in Expansions.cfg, and the log for "the event chooser could not be
      built".

   3. Run "Run all diagnostics probes" from the Actions tab.
      PASS: 53 results and a report path in the output pane.
      FAIL: the plain IMGUI "Schedule I Expansions" window instead of the native screen (the
      injector never landed), or far fewer than 53 results (a module did not enable).
      While you are in the report, read drivers.vehicle_agent. At least one owned vehicle listed
      as "self-drives: yes" means you get the real driving path; all "no" is not a bug, but every
      trip will relay.

   4. HIRING. Talk to the employee fixer: choose to hire an employee, choose Driver in the type
      list, then choose the location.
      PASS: only one Driver type choice exists (no per-property top-level clutter); every eligible
      location appears on the next screen; Barn and Docks Warehouse allow two drivers; ordinary
      employee capacity is ignored; Car Wash/Laundromat/Post Office/Taco Ticklers do not appear;
      the NPC's visible position at that property is verified before charging, and a persistent
      16-slot Veeper is parked.
      FAIL: run drivers.hiring_desk; it names the exact missing hook or scene object.

   5. THE CLIPBOARD. Point the management clipboard at that driver.
      PASS: the header says Driver (not Handler), the NPC keeps its stable vanilla appearance, and
      the panel shows Bed plus five Route rows with no text overlap; Stations is hidden. Set the Bed. Put one unrelated
      product in the Veeper, then set a route's pickup with the worldspace picker -- hovering
      a container at a DIFFERENT property must refuse with "Driver X only collects from the Barn".
      Set a drop-off at another property you own; the vanilla out-of-range refusal must be
      overturned.
      Talk to the driver and choose "Set off now". PASS: they load one available batch, leave
      without waiting for the normal threshold, the destination stock goes up, and the unrelated
      Veeper cargo remains untouched. FAIL: press F6 and read the no-work reason.

   6. Start a trip and then sleep through it.
      PASS: you wake to "Delivery completed while you slept" and the cargo is at the far end.
      FAIL: a van parked mid-junction, a driver stuck in a non-Idle state, or cargo that vanished.

   7. THE SALE LOOP. "Bring a group into town now", then "Make the group offer now", accept on the
      phone, and complete the handover.
      PASS: an offer message arrives WITH RESPONSE BUTTONS, you accept, the leader walks to the
      meeting point, and the shipped handover screen pays you with real XP.
      FAIL at the offer: run "Why can't I sell to them?" and read which of the six stages it stops
      at. A stop at stage 2 with a "leader already holds an offer" note means "Clear the group's
      stuck order" and try again. A stop at stage 4 means the message reached the phone with no
      response buttons, which cannot be accepted.
      Also WALK UP TO A GROUP MEMBER AND TALK TO THEM: the leader must offer "About the <group>
      order", non-leaders "Talk business", and the shipped "complete contract" choice must still
      be in the list. THIS IS THE ONE FEATURE LOOP IN THE SUITE THAT HAS NEVER COMPLETED.

   8. POLICE. First run police.officers and check the town HAS police -- scene total, awake and
      dead. If it reads mostly dead, "Put the police back on duty" and re-run; on an old save this
      is the difference between the whole module working and it silently doing nothing.
      Then "Heat +25" twice and walk past a patrol. Then get arrested while carrying less cash
      than the fine.
      PASS: police.world_state reports a driven intensity above the vanilla baseline; the notice
      shows the multiplied figure; cash goes to zero and the shortfall comes off your ONLINE
      balance; AND YOUR PHONE HAS A TEXT FROM "Dispatch Office" itemising it. Then use the Up
      arrow: "Put a raid on the clock", go and stand in the named property, and confirm the raid
      is aborted rather than emptying your containers.
      FAIL, no text: run police.messages -- the Dispatch contact did not come up, and everything
      substantive will have fallen back to toasts.

   9. QUALITY OF LIFE. Order a delivery from the phone and read the quote, then check
      "Show delivery timing".
      PASS: the quote is about half the vanilla figure and the countdown agrees with it. Tick the
      auto-reorder box on that row and confirm it repeats itself once the first one lands.
      IF YOU HAVE AN ORDER SHOWING AN ABSURD ARRIVAL TIME, that is the bug in 8.4 -- it should be
      repaired automatically at load. "Repair stuck deliveries" is the manual handle.

  10. Save, quit to the main menu, reload the same save, and re-run the whole probe suite.
      PASS: heat records, the driver roster and trip counters, the clipboard's route rows, the
      group state and the standing auto-reorders all come back identical, and
      identity.player_code matches the earlier report.

  One thing NOT on this list on purpose: do not enable allow_mutating_probes. The read-only
  police.tuning_writability already answers the question police.tuning_statics exists to confirm,
  and that probe has killed the game process before.

 15.  KNOWN LIMITATIONS AND WARNINGS
==================================================================================================

  --------------------------------------------------------------------------------------------
  DRIVER FULL TRIP STILL NEEDS ONE END-TO-END PLAYTEST                       *** IMPORTANT ***
  --------------------------------------------------------------------------------------------
  Native hiring is fixed and runtime-verified: the 0.4.6f12 probe found the employee fixer and 13
  attached driver choices. All patches, endpoints, parking lots and VehicleAgents also verified.
  What has not yet been observed in one uninterrupted run is hire -> bed -> clipboard route ->
  Veeper load -> road trip -> deposit -> save/reload. Section 14 gives that exact test. HD-P14
  additionally proves unrelated trunk cargo and the same-product baseline survive the delivery.

  --------------------------------------------------------------------------------------------
  THE SPECIAL CUSTOMERS SALE LOOP HAS NEVER COMPLETED
  --------------------------------------------------------------------------------------------
  The pool exists, is registered, and stays on post. The product allow-list resolves against the
  live item registry. What has never been observed end to end is arrive -> offer -> accept on the
  phone -> handover -> payment. Both round-1 bugs in that path are fixed in source and neither fix
  has been seen working. sc.sale_loop and "Why can't I sell to them?" exist precisely to tell you
  which of the six stages it stops at.

  --------------------------------------------------------------------------------------------
  THREE VISITOR VOICES ARE REJECTED AT PREFAB TIME
  --------------------------------------------------------------------------------------------
  Cosmetic, and visible in the log on every load:

     [WARNING] Voice 'female1' was rejected for expansions_sc_visitor_02 ... Supported
     identifiers: cold, crackhead, female-1, female-2, goblin, hippie, joel, monotone, redneck,
     timid, tyler ... it keeps the base prefab's voice.

  The mod asks for "female1"/"female2"; S1API 3.1.7 wants "female-1"/"female-2". Three of the
  eight pool members keep the base prefab's voice instead. Nothing else is affected -- the voice
  call is deliberately isolated in its own try/catch precisely so a typo cannot lose the prefab.

  --------------------------------------------------------------------------------------------
  THE SCOUT STILL DRIFTS; THE WATCHDOG PUTS HIM BACK
  --------------------------------------------------------------------------------------------
  The Westville sighting is explained and contained, not eliminated. Custom S1API NPCs get the
  generic civilian schedule and participate in curfew, so they walk. pin_visitor_schedules stops
  most of it and post_watchdog catches the rest -- but the log still shows corrections of around
  20 m, which means something is still moving him between checks. If you see him somewhere he
  should not be for more than a fraction of a second, say so.

  --------------------------------------------------------------------------------------------
  THE TWO DEFAULTS THAT FIGHT EACH OTHER
  --------------------------------------------------------------------------------------------
  Police Improvements' debt lever assumes the vanilla $10,000 weekly ATM ceiling -- that scarcity
  is the whole reason taking a fine out of the online balance hurts. Quality of Life raises that
  ceiling to $25,000 by default. Both are shipping as the owner asked for them; be aware that
  running both at their defaults makes arrests meaningfully cheaper. Set weekly_deposit_limit =
  10000 to get the pressure back.

  --------------------------------------------------------------------------------------------
  DISABLE, DO NOT DELETE                                                    *** IMPORTANT ***
  --------------------------------------------------------------------------------------------
  A save-persisted custom NPC cannot be unmade by a toggle. S1API builds the eight Special
  Customers visitors from the types in that assembly DURING SAVE LOAD, before any module toggle is
  read. Disabling the module stops everything the mod DOES -- no visits, no offers, no dressing --
  but the NPCs stay in the world and in the save. Destroying a save-persisted networked NPC
  mid-session risks corrupting the save, so the module deliberately does not try.

  Removing the DLL is what removes them, and that ORPHANS THEIR FOLDERS in every save that stored
  them. Whether the vanilla NPC loader tolerates orphaned folders is an open question with a
  written test recipe (SC-V6) in the probe report.

  Use the toggle on the Mods tab, or set enabled = false in Expansions.cfg. Do not delete the DLL
  from Mods\. The updater follows the same rule: it never deletes a mod DLL, and it preserves a
  *.dll.disabled you created yourself.

  The other three mods do not have this problem. Drivers are real vanilla employees created by the
  game's own factory. Federal agents have ShouldSave forced false and are removed from both
  registries on despawn. Quality of Life owns no world objects at all.

  --------------------------------------------------------------------------------------------
  MULTIPLAYER AND HOST AUTHORITY
  --------------------------------------------------------------------------------------------
  - The expansion mods are HOST-AUTHORITATIVE. All world mutation is gated on
    InstanceFinder.NetworkManager == null || InstanceFinder.IsServer. The null check is
    load-bearing: single-player has no NetworkManager at all, so a bare IsServer check would
    disable the mods outside multiplayer.
  - A co-op guest gets a read-only surface. Host-only actions grey themselves out naming the
    reason rather than silently doing nothing. A guest can still teleport to things and read
    status -- moving your own camera is client-side.
  - ALL PLAYERS SHOULD INSTALL THE SAME MODS. There are no custom network messages: the game runs
    FishNet v3, and FishNet's code generator never runs against mod assemblies on IL2CPP, so
    custom RPCs, SyncVars and spawnable prefab ids are simply unavailable.
  - Custom NPC prefabs are registered by simple type name and the ordering is load-order
    sensitive, so co-op peers must agree on emission order. sc.visitor_prefab dumps that ordering
    -- diff it between two machines before trusting co-op.
  - The auto-reorder engine and the deposit-limit offset are host-gated the same way.

  --------------------------------------------------------------------------------------------
  FEDERAL AGENTS: THE CLONE PATH INHERITS THE DONOR'S NPC ID
  --------------------------------------------------------------------------------------------
  On this build agents spawn via the clone path (the log says so). A cloned agent inherits the
  donor officer's NPC id, because the id lives on a shared asset and rewriting it would rename
  every officer in the game. So you will have two NPCs answering to the same id. They are
  distinguished by native pointer, never added to the officer pool, and cannot reach the save --
  but anything that looks an officer up by id can find the wrong one.

  --------------------------------------------------------------------------------------------
  WRITING AN IL2CPP CONST KILLS THE PROCESS
  --------------------------------------------------------------------------------------------
  Codebase-wide danger, and the reason allow_mutating_probes exists and defaults off.
  Il2CppInterop projects a const and a real static as the same read/write property. The setter is
  a bare il2cpp_field_static_set_value which, unlike Mono's, has NO literal guard: it computes
  klass->static_fields + offset and memcpys. A const contributes no storage, so on a class whose
  statics are all const that base pointer is null -- access violation, process gone, nothing
  catchable, no crash log. Reads are fine.

  28 of the 31 police tuning statics are consts. GameReflection.TryWriteStatic now refuses
  const-inlined statics, and the crash journal quarantines any subject the process died on. This
  is also why Quality of Life never writes the ATM ceiling directly and carries an offset on the
  counter instead.

  --------------------------------------------------------------------------------------------
  SPECIAL CUSTOMERS AND THE OFFICIAL FEATURE
  --------------------------------------------------------------------------------------------
  TVGS is shipping their own Special Customers as v0.5.0. The detector described in section 7
  fails closed, so updating past 0.4.6 should stand the module down on its own. That has never
  been tested against a real 0.5.0 build. If the version cannot be parsed the module disables,
  which is the safe direction.

  --------------------------------------------------------------------------------------------
  MODULE ERROR HANDLING
  --------------------------------------------------------------------------------------------
  A module that throws 10 times in one frame hook during a single enable cycle is switched off for
  the rest of the session. The PERSISTED toggle stays on, so it retries on next launch. If a
  module keeps disappearing from the active set, check the MelonLoader log for the ten error lines
  that preceded it.

  --------------------------------------------------------------------------------------------
  A GAME UPDATE INVALIDATES EVERYTHING
  --------------------------------------------------------------------------------------------
  The interop assemblies every DLL here is compiled against are a projection of GameAssembly.dll.
  A game patch replaces that file, MelonLoader regenerates the assemblies on the next launch (a
  multi-minute wait that needs internet), and mods compiled against the old layout may bind to the
  wrong things or fail outright. The auto-updater cannot help with this: it can install a new
  build, but somebody has to compile one first.
